## 1. How a company becomes a working board

1. **Config.** `data/companies.csv` (`slug,name,website,industry,tier,enabled,h1b_petitions_recent`) and `data/boards.csv`
   (`company_slug,board_slug,board_url,monitor_type,monitor_config,scraper_type,scraper_config`). Most rows were generated by
   `scripts/build_csvs.py`, which copies jobseek's crawler CSVs and adds 102 hand-curated companies.
   Sample: `anthropic,anthropic-careers,https://job-boards.greenhouse.io/anthropic,greenhouse,{"token":"anthropic"},skip,`.
2. **Sync** (`src/sync.py`):
   - Companies: only `slug,name,website,tier` reach the `company` table (`:42`). `industry`, `enabled` and `h1b_petitions_recent` are ignored.
   - Boards (`:186-300`):
     - `monitor_type` goes to `job_board.crawler_type`.
     - `monitor_config` becomes `job_board.metadata` JSONB, with `scraper_type` and `scraper_config` nested inside.
     - Browser flags are derived from the type and config.
     - `throttle_key` is set at `:135`: the monitor name for API monitors, otherwise the board hostname.
   - Every board is then queued in Redis with `enqueue_monitor` (`:329`).
3. **Adding companies by hand:** `myjobs company add` supports only about 6 ATS types (`src/cli.py:58,525`).
4. **Automatic discovery exists but is not wired into the daily run:**
   - `src/workspace/career_discover.py:851` `discover_career_pages` works in four phases:
     1. Careers links on the homepage, matched with a multilingual path regex.
     2. Follow those links and run each monitor's `can_handle`.
     3. One more hop.
     4. Blind ATS slug probes derived from the domain (`_BLIND_PROBE_TEMPLATES`, `:62`).
   - ATS fingerprinting: `detect_monitor_type` (tries monitors in cost order) and `probe_all_monitors`, both in `src/core/monitors/__init__.py:252,542`.
   - Only the `ws` agent workspace uses these (`src/workspace/commands/config.py:484,903`, `commands/crawl.py:398`, `lib/probe.py:217`).
   - **This is the starting point for the Phase 2B discovery pipeline.**

## 2. Monitors (discovery) and scrapers (detail)

"Rich" monitors return full job data, so the scraper is `skip`. URL-only monitors return URLs that a scraper then fetches.
Monitors are registered in cost order (`register(...)` at the end of each `src/core/monitors/*.py`).

| Class | Monitor types | Method |
|---|---|---|
| Official public JSON API, rich | greenhouse, ashby, lever (US and EU), gem, pinpoint, recruitee, hireology, dvinci, mokahr, almacareer (GraphQL), recruiter_co_kr, traffit, deel, amazon, oracle_hcm, jobylon, rss (SuccessFactors/Teamtailor feeds) | Documented or public candidate-facing endpoints |
| Public API, URL-only | workday (`/wday/cxs` POST), smartrecruiters, workable (v3), breezy, rippling, bite | API listing, then a scraper for detail |
| Embedded/HTML, no browser | personio (XML), softgarden, umantis, join (`__NEXT_DATA__`), ycombinator, phenom (sitemap), eightfold (sitemap + PCSX API), notion (`/api/v3`) | Parse page data |
| Generic or browser | sitemap (cost 50), nextdata (20), inline (60), api_sniffer (80, Playwright), dom (100, Playwright if `render`), accenture (always browser) | Fallbacks |

Scrapers (`src/core/scrapers/`): skip, json-ld, nextdata, dom, embedded, pdf, api_sniffer (browser), plus ATS-specific scrapers for
workday, smartrecruiters, workable, eightfold, oracle_hcm, notion, rippling, mokahr and bite. With no scraper set, the code uses the
monitor's default, then `dom` (`src/workers/pipeline.py:221`).

**Board counts (config).**
- Monitors: greenhouse 1,561 · ashby 695 · dom 124 · lever 121 · join 110 · api_sniffer 107 · workday 106 · pinpoint 62 · sitemap 51 · recruitee 48 · rss 43 · smartrecruiters 25 · workable 17 · eightfold 15 · oracle_hcm 13 · nextdata 12 · about 25 other types with ≤8 boards each.
- Scrapers: skip 2,641 · json-ld 114 · nextdata 112 · dom 101 · workday 98 · others small.
- **2,722 of 3,169 boards (86%) use public candidate-facing ATS APIs or feeds.** That's a good politeness baseline.

## 3. Pagination and generic fallbacks
- **dom:**
  - Steps through a URL template or query parameter (`start`, `increment`, `max_pages` ≤ 10,000).
  - Stops on 404/410 or when a page adds no new URLs.
  - Can paginate in the browser (`dom.py:277-363`).
- **sitemap:**
  - Finds sitemaps by walking up the path, trying common paths, then reading `Sitemap:` lines in robots.txt (`sitemap.py:214-343`).
  - Recurses into sitemap indexes and filters URLs by job keywords.
  - Caps at 50k URLs.
- **workday:**
  - Pages 20 at a time; at the 2,000-result cap it splits the query by facet.
  - Finds a tenant's sites through robots.txt.
- **nextdata:** `__NEXT_DATA__` and React Router data. Paginates by page count or by total ÷ page size.
- **api_sniffer:** records XHR calls in Playwright and replays them (`MAX_PAGES=50`, `MAX_ITEMS=10k`).
- **Incremental** (`_incremental.py`, eightfold): stops paging once results are older than the last seen watermark.
- **Structured data:** JSON-LD `JobPosting` exists only as a *scraper* (`scrapers/jsonld.py`). `embedded` handles script-tag and `window.X=` data. JSON-LD is not used for discovery.

## 4. Failures, retries, rate limits, caching
- **Rate limiting** is per throttle key, in Redis (`ratelimit:{key}`, checked atomically in `src/lua/claim_work.lua`).
  - Delay: 0.5 s for known ATS keys, 2.0 s otherwise (`src/redis_queue.py:196`, `src/config.py:28`).
  - All 1,561 greenhouse boards share **one** 0.5 s key. That's polite toward the ATS but serializes the work.
- **Retries:** `fetch_with_retry` (`src/shared/http_retry.py:60-105`).
  - 3 attempts with exponential backoff and jitter; retries 408, 425, 429 and 5xx.
  - When retries run out it raises `PaginationFetchError`, so the run fails loudly instead of silently truncating.
  - **`Retry-After` is not honored.**
- **Board health** (`src/queries/monitor.py:162-174`, `src/processing/board.py:481-506`):
  - Each failure adds a strike and backs off min(5·2ⁿ min, 24 h).
  - At 5 strikes the board is disabled (`is_enabled=false`, `board_status='disabled'`).
  - Postings are delisted only when the last success is stale.
  - A guard on sudden job-count drops and an empty-check counter prevent false "gone" marks.
- **Queue:** 3 priority tiers × 2 worker types (HTTP, browser). 600 s leases with a 120 s heartbeat, a reaper every 30 s, and dead letter after 5 strikes.
- **Caching and staging:** descriptions go into the `descriptions` table and content is hashed (`r2_stage.py`). The R2 upload path exists but is never called. There's no HTTP-level cache (ETag/If-Modified-Since).

## 5. SSRF guard (`src/shared/ssrf.py`)
- **What it blocks:** loopback, link-local and cloud metadata, private, multicast, reserved and unspecified addresses, including IPv4 embedded in IPv6.
- **How it checks:** `resolve_host_or_raise` resolves the host and rejects it if *any* returned address is blocked.
- **Coverage:** `SSRFGuardedTransport` checks every request, including each redirect hop (`:346`). There is an `INTERNAL_HOSTS_ALLOW` allowlist.
- **Gap 1 (DNS rebinding window):** the resolved IP is not pinned for the actual connect, so a DNS answer can change between the check and the connection.
- **Gap 2 (bypass):** the guard is attached only in `src/shared/http.py:_build_async_client`. **`myjobs run` passes a plain `httpx.AsyncClient` (`src/cli.py:85`)**, so most boards run with no SSRF check, the default httpx User-Agent and no certifi context. The guarded client is built only for proxy and `ssl_verify:false` boards (`processing/board.py:686`, `processing/scrape.py:1287`).

## 6. Identification, robots.txt, ToS posture
| Aspect | Today | Concern |
|---|---|---|
| User-Agent | Fake Chrome 131 (`http.py:48`); the sitemap monitor sends `jobseek-crawler (+https://jseek.co/)` (`sitemap.py:33`) | Not honest. The sitemap UA claims to be someone else's crawler |
| robots.txt | Read only to find sitemaps and Workday sites. **Never used to allow or deny** | Breaks the "respect the web" rule |
| TDM opt-out | `tdm.py` honors `tdm-reservation: 1` (header or meta) as a clean skip | Good |
| Stealth | Playwright `stealth: true` (new headless Chrome, `browser.py:303`); an `ssl` tweak. **No curl_cffi or TLS-fingerprint spoofing** (the claim in the notes is outdated) | Evasion-flavored |
| Proxies | 24 boards need `"proxy": true` (Webshare/Decodo) | ToS and evasion risk |
| Aggregators | No Naukri or LinkedIn scrapers exist | Good, keep it that way |

## 7. Where coverage breaks
1. **Browser boards are silently dropped.** About 120 boards need a browser for discovery and about 92 for scraping. `myjobs run` never starts browser workers.
2. **The daily run uses the plain httpx client** (§5), so some hosts that need the configured UA or certifi context probably fail.
3. **Workday:** 13 of 25 failed with "0 jobs" in the May health check, likely tenant/site config drift (52% failure).
4. **Eightfold** 20% failing, **sitemap** 9.8%, **api_sniffer** 5.6% (May SQLite).
5. **Proxy-only boards (24)** fail without a proxy.
6. **Themes in the jobseek knowledge base** (`src/workspace/kb/`, 105 notes): api_sniffer picks the wrong endpoint or field (~18), sitemaps full of non-job URLs (~18), dom junk links or first page only (~12), Phenom/Eightfold/iCIMS/Wix browser timeouts, Workday multi-site oddities, slug guesses matching the wrong company (Personio, Rippling), hard caps (Eightfold 2,000 offset, 10k API caps).
7. **India coverage is thin.** No country column in config. Only about 8 company rows and 12 board rows match Indian city or country names. In May, 799 of 16,342 jobs (4.9%) were located in India. **None of the ATS platforms common in India (Darwinbox, Keka, Zoho Recruit, Freshteam, …) have monitors**; to be verified in Phase 2B.
8. **No tests** cover monitors or scrapers (fixed by `tests/characterization/` in Phase 0).
9. `crawler board SLUG` is broken (imports `run_board_test`, which doesn't exist).
